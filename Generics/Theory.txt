Generics were introduced in Java 5 to provide **compile-time type safety** and eliminate the need for constant type casting. They allow you to write reusable, flexible code that works with different data types while catching errors before you even run your program.

Let’s break this down from the absolute basics to advanced concepts.

---

## 1. The "Why": Life Before Generics

Before Generics, standard collections like `ArrayList` held raw `Object` types. This caused two major problems: you had to manually cast objects back to their original type, and you could accidentally put the wrong type into a list, causing a runtime crash.

**Before Generics (The Bad Way):**

```java
List list = new ArrayList(); 
list.add("Hello");
list.add(100); // The compiler allows this!

// Later in the code...
String text = (String) list.get(0); // Requires manual casting
String text2 = (String) list.get(1); // RUNTIME ERROR: ClassCastException (Integer cannot be cast to String)

```

**After Generics (The Safe Way):**

```java
List<String> list = new ArrayList<>();
list.add("Hello");
// list.add(100); // COMPILE ERROR! The IDE stops you immediately.

String text = list.get(0); // No casting needed.

```

---

## 2. The Basics: Generic Classes

You can create your own classes that accept a type parameter. We use angle brackets `< >` to specify the type.

```java
// T stands for "Type". It acts as a placeholder.
public class Box<T> {
    private T content;

    public void set(T content) {
        this.content = content;
    }

    public T get() {
        return content;
    }
}

```

**How to use it:**

```java
Box<Integer> intBox = new Box<>();
intBox.set(123);

Box<String> strBox = new Box<>();
strBox.set("Java");

```

> **Standard Type Naming Conventions:**
> * **`E`** - Element (used extensively by the Java Collections Framework)
> * **`K`** - Key
> * **`V`** - Value
> * **`N`** - Number
> * **`T`** - Type
> 
>

## 3. Generic Methods

You don't have to make a whole class generic. You can apply generics to individual methods. The type parameter `<T>` must be declared *before* the return type.

```java
public class Printer {
    
    // <T> declares the generic type for this specific method
    public <T> void printArray(T[] array) {
        for (T item : array) {
            System.out.println(item);
        }
    }
}

```

---

## 4. Intermediate: Bounded Type Parameters

Sometimes, you want to restrict the types that can be used. For example, you might want a generic method to only accept numbers (`Integer`, `Double`, `Float`, etc.). You do this using the `extends` keyword.

```java
// T must be a subclass of Number (or Number itself)
public <T extends Number> double addNumbers(T num1, T num2) {
    return num1.doubleValue() + num2.doubleValue();
}

```

If you try to call `addNumbers("Hello", "World")`, the compiler will throw an error because `String` does not extend `Number`.

---

## 5. Advanced: Wildcards (`?`)

Wildcards are used when you want a generic type to be a bit more flexible, particularly when passing collections as parameters. There are three types of wildcards:

### A. Unbounded Wildcard (`?`)

Used when you don't care about the type at all.

```java
public void printList(List<?> list) {
    for (Object elem : list) {
        System.out.println(elem);
    }
}

```

### B. Upper Bounded Wildcard (`? extends T`)

Accepts `T` or any **subclass** of `T`.
*Use case:* When you want to **READ** from a collection.

```java
// Accepts List<Number>, List<Integer>, List<Double>, etc.
public void processNumbers(List<? extends Number> list) {
    for (Number n : list) {
        System.out.println(n); // Safe to read as Number
    }
    // list.add(10); // ERROR! You cannot add to an upper-bounded wildcard collection.
}

```

### C. Lower Bounded Wildcard (`? super T`)

Accepts `T` or any **superclass** of `T`.
*Use case:* When you want to **WRITE** to a collection.

```java
// Accepts List<Integer>, List<Number>, List<Object>
public void addIntegers(List<? super Integer> list) {
    list.add(50); // Safe to add an Integer
}

```

---

## 6. The Golden Rule of Wildcards: PECS

If you want to master advanced generics, remember **PECS: Producer Extends, Consumer Super**.

* **Producer (`? extends T`):** If you need a List to produce `T` values (you want to read from the list), declare it with `? extends T`. (But you cannot add to it).
* **Consumer (`? super T`):** If you need a List to consume `T` values (you want to write/add to the list), declare it with `? super T`.

## 7. Under the Hood: Type Erasure

This is a favorite Java interview question. Generics exist **only at compile-time**.

Once your code is compiled, Java removes (erases) all generic type information and replaces it with `Object` (or the bounding type, if you used `extends`). This is called **Type Erasure**. It was done to ensure backward compatibility with older versions of Java (Java 4 and below).

Because of Type Erasure, **you cannot do the following in Java**:

1. **Instantiate a generic type:** `T obj = new T();` (Error: `T` doesn't exist at runtime)
2. **Create generic arrays:** `T[] array = new T[10];` (Error)
3. **Use `instanceof` with generics:** `if (obj instanceof List<String>)` (Error: At runtime, it's just `List`)



































Because of Type Erasure, Java throws away generic type information at runtime. This means if you have a class `<T>`, the JVM has no idea what `T` actually is when the program runs.

Because of this, you cannot do things like `new T()` or `new T[10]`.

To bypass this limitation, we use a **Class Token** (`Class<T>`). By explicitly passing the `.class` of the type you want to work with, you give the JVM a physical object at runtime that represents the type. You can then use Java's **Reflection API** to create arrays and instantiate objects.

Here are the two most common ways to use Class tokens to bypass Type Erasure.

### 1. Creating Generic Arrays

You cannot write `T[] array = new T[10];`. Instead, you pass `Class<T>` into the constructor and use `java.lang.reflect.Array.newInstance()`.

```java
import java.lang.reflect.Array;

public class GenericArray<T> {
    private T[] array;

    // We pass Class<T> as a "token" so the class knows its type at runtime
    @SuppressWarnings("unchecked")
    public GenericArray(Class<T> type, int size) {
        // array = new T[size]; // COMPILE ERROR: Generic array creation
        
        // SUCCESS: Using Reflection to create the array
        this.array = (T[]) Array.newInstance(type, size);
    }

    public void set(int index, T value) {
        array[index] = value;
    }

    public T get(int index) {
        return array[index];
    }

    public static void main(String[] args) {
        // We pass String.class as the token
        GenericArray<String> stringArray = new GenericArray<>(String.class, 5);
        stringArray.set(0, "Reflection");
        System.out.println(stringArray.get(0));
    }
}

```

### 2. Instantiating Generic Objects

You cannot write `T item = new T();`. Instead, you use the Class token to look up the default constructor and invoke it via reflection.

```java
public class GenericFactory<T> {
    private Class<T> type;

    public GenericFactory(Class<T> type) {
        this.type = type;
    }

    // Creates a new instance of T using Reflection
    public T createNewInstance() {
        try {
            // Tries to find a no-argument constructor and create an object
            return type.getDeclaredConstructor().newInstance();
        } catch (Exception e) {
            throw new RuntimeException("Cannot instantiate type: " + type.getName(), e);
        }
    }

    public static void main(String[] args) {
        // We pass StringBuilder.class as the token
        GenericFactory<StringBuilder> factory = new GenericFactory<>(StringBuilder.class);
        
        // Successfully creates a new StringBuilder at runtime
        StringBuilder sb = factory.createNewInstance();
        sb.append("Created via Reflection!");
        
        System.out.println(sb.toString());
    }
}

```

### The "Super Type Token" Pattern (How Libraries Do It)

If you've ever used JSON parsing libraries like Jackson or Gson, you might have wondered how they can deserialize a JSON string directly into a `List<User>` if the `List` forgets it holds `User`s at runtime.

They bypass type erasure using an anonymous subclass. While Java erases types from *instances*, it **keeps generic types in the class signature itself**.

```java
// How libraries like Gson or Jackson capture erased types:
TypeReference<List<String>> typeRef = new TypeReference<List<String>>() {};

```

By adding `{}` at the end, you are creating an anonymous subclass. Because it's a subclass, Java permanently compiles `List<String>` into the bytecode of that new anonymous class, allowing the library to read it back at runtime using `getClass().getGenericSuperclass()`.
