Weighted Graph Representation:

Suppose:
0---4--->1
0---2--->2
1---6--->2

Store:
0 → (1,4),(2,2)
1 → (0,4),(2,6)
2 → (0,2),(1,6)

In Java, define a small helper class:

class Pair {
    int node;
    int weight;

    Pair(int node, int weight) {
        this.node = node;
        this.weight = weight;
    }
}

Then:

ArrayList<ArrayList<Pair>> graph = new ArrayList<>();

for (int i = 0; i < n; i++) {
    graph.add(new ArrayList<>());
}

graph.get(0).add(new Pair(1, 4));
graph.get(1).add(new Pair(0, 4));

graph.get(0).add(new Pair(2, 2));
graph.get(2).add(new Pair(0, 2));

This is the representation commonly used for algorithms like Dijkstra, Prim's, and Bellman-Ford.

DFS vs BFS:
| DFS                                                              | BFS                                                                |
| ---------------------------------------------------------------- | ------------------------------------------------------------------ |
| Goes deep first                                                  | Explores level by level                                            |
| Uses Recursion/Stack                                             | Uses Queue                                                         |
| Good for connected components, cycle detection, topological sort | Good for shortest path in unweighted graphs, level order traversal |
| Path may not be shortest                                         | Finds shortest path (unweighted graph)                             |

Stop writing neighbour code every time.

I always write this first.

int[] dr = {-1, 1, 0, 0};
int[] dc = {0, 0, -1, 1};

Then

for (int k = 0; k < 4; k++) {
    int nr = row + dr[k];
    int nc = col + dc[k];
}

You'll use this in almost every 4-direction grid problem.

For 8-direction movement:

int[] dr = {-1,-1,-1,0,0,1,1,1};
int[] dc = {-1,0,1,-1,1,-1,0,1};

Never memorize neighbour code separately again.
