If you're solving competitive programming problems, Fast I/O is one of the most important optimizations in Java. The default classes (Scanner and System.out.println) are convenient but often too slow for large inputs.

Why is Scanner slow?

Scanner:

Parses input using regular expressions.
Performs many checks.
Is easy to use but slower.

For problems with 10⁵–10⁶ numbers, it can cause Time Limit Exceeded (TLE).

Instead, competitive programmers use:

BufferedInputStream or BufferedReader for input.
StringBuilder + PrintWriter for output.
Method 1: BufferedReader (Easy)
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws Exception {

        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));

        int n = Integer.parseInt(br.readLine());

        StringTokenizer st = new StringTokenizer(br.readLine());

        for(int i = 0; i < n; i++) {
            int x = Integer.parseInt(st.nextToken());
            System.out.println(x);
        }
    }
}
How it works

Suppose input is

5
10 20 30 40 50

br.readLine() reads:

"10 20 30 40 50"

StringTokenizer splits it into

10
20
30
40
50
Method 2: FastReader (Most Popular)

Most Java CP coders create their own class.

import java.io.*;
import java.util.*;

class FastReader {
    BufferedReader br;
    StringTokenizer st;

    FastReader() {
        br = new BufferedReader(new InputStreamReader(System.in));
    }

    String next() throws IOException {
        while (st == null || !st.hasMoreElements()) {
            st = new StringTokenizer(br.readLine());
        }
        return st.nextToken();
    }

    int nextInt() throws IOException {
        return Integer.parseInt(next());
    }

    long nextLong() throws IOException {
        return Long.parseLong(next());
    }

    double nextDouble() throws IOException {
        return Double.parseDouble(next());
    }

    String nextLine() throws IOException {
        return br.readLine();
    }
}

Use it like this:

public class Main {

    public static void main(String[] args) throws Exception {

        FastReader in = new FastReader();

        int n = in.nextInt();

        for(int i = 0; i < n; i++) {
            int x = in.nextInt();
            System.out.println(x);
        }
    }
}

This is already much faster than Scanner.

Method 3: Ultra Fast I/O (Used by Experts)

For Codeforces, AtCoder, and other strict judges, people use a byte-buffer approach.

import java.io.*;

class FastScanner {

    private final InputStream in = System.in;
    private final byte[] buffer = new byte[1 << 16];

    private int ptr = 0, len = 0;

    private int read() throws IOException {

        if(ptr >= len){
            len = in.read(buffer);
            ptr = 0;
            if(len <= 0) return -1;
        }

        return buffer[ptr++];
    }

    int nextInt() throws IOException {

        int c;

        while((c = read()) <= ' ');

        int sign = 1;

        if(c == '-') {
            sign = -1;
            c = read();
        }

        int val = 0;

        while(c > ' ') {
            val = val * 10 + c - '0';
            c = read();
        }

        return val * sign;
    }
}

This is among the fastest Java input methods.

Fast Output

Avoid printing inside loops:

❌ Slow

for(int i=0;i<n;i++)
    System.out.println(arr[i]);

Instead:

StringBuilder sb = new StringBuilder();

for(int i=0;i<n;i++)
    sb.append(arr[i]).append('\n');

System.out.print(sb);

Even better:

PrintWriter out = new PrintWriter(System.out);

out.println(answer);

out.flush();
Complete Competitive Programming Template
import java.io.*;
import java.util.*;

public class Main {

    static class FastReader {

        BufferedReader br;
        StringTokenizer st;

        FastReader() {
            br = new BufferedReader(new InputStreamReader(System.in));
        }

        String next() throws IOException {
            while (st == null || !st.hasMoreTokens())
                st = new StringTokenizer(br.readLine());
            return st.nextToken();
        }

        int nextInt() throws IOException {
            return Integer.parseInt(next());
        }

        long nextLong() throws IOException {
            return Long.parseLong(next());
        }

        double nextDouble() throws IOException {
            return Double.parseDouble(next());
        }

        String nextLine() throws IOException {
            return br.readLine();
        }
    }

    public static void main(String[] args) throws Exception {

        FastReader in = new FastReader();
        PrintWriter out = new PrintWriter(System.out);

        int n = in.nextInt();

        long sum = 0;

        for(int i = 0; i < n; i++)
            sum += in.nextInt();

        out.println(sum);

        out.flush();
    }
}
Which one should you use?
Method	Speed	Difficulty	Recommended
Scanner	Slow	Very Easy	❌ No (for CP)
BufferedReader + StringTokenizer	Fast	Easy	✅ Yes
FastReader wrapper	Fast	Easy	⭐ Best for beginners/intermediate
Custom BufferedInputStream/byte-buffer scanner	Very Fast	Moderate	⭐ Best for advanced CP
Recommendation

If you're starting competitive programming in Java, use the FastReader + PrintWriter template. It's simple, readable, and fast enough for the vast majority of problems. Once you're comfortable and encounter tighter time limits, you can switch to the byte-buffer implementation.
